# ป้ายระบุและควบคุมการใช้จัมโบ้ (Jumbo QR Tracker)

เว็บแอปสำหรับติดตามจำนวนครั้งการใช้งานถุงจัมโบ้ (Jumbo bag) แต่ละใบด้วย QR Code
**ข้าวไทยไม่เกิน 20 ครั้ง / ข้าวญี่ปุ่นไม่เกิน 5 ครั้งต่อจัมโบ้** พร้อมบันทึกความสะอาด/
ความสมบูรณ์ ผู้บันทึก ผู้ตรวจสอบ และหมายเหตุ ทุกครั้งที่ใช้งาน

**ข้อมูลทั้งหมดเก็บอยู่ใน Google Sheet ของคุณเอง** (อยู่ใน Google Drive / นับรวมในโควตา
Google One ของบัญชีคุณ) เปิดดู/ตรวจสอบข้อมูลดิบตรงจาก Sheet ได้ตลอดเวลาเหมือนไฟล์ Excel
ทั่วไป — ไม่ต้องพึ่งบริการอื่นเพิ่มเติม

เป็นไฟล์เว็บ static (`index.html`) ไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง — โฮสต์บน
GitHub Pages ได้ฟรี ส่วนฐานข้อมูลใช้ Google Sheet ผ่านตัวกลาง Google Apps Script

## ฟีเจอร์

- เพิ่ม/ลบจัมโบ้ได้เอง เลือกชนิดข้าว (ข้าวไทย / ข้าวญี่ปุ่น) — เลขจัมโบ้นับแยกกันคนละชุดต่อชนิด
- **กำหนดจำนวนครั้งสูงสุดแยกตามชนิดข้าว**: ข้าวไทย 20 ครั้ง, ข้าวญี่ปุ่น 5 ครั้ง (ตรวจสอบทั้งฝั่งเว็บและฝั่ง Google Sheet)
- **ฟิลเตอร์ดูตามชนิดข้าว** ในหน้ารายการจัมโบ้: ทั้งหมด / ข้าวไทย / ข้าวญี่ปุ่น
- **เข้าสู่ระบบด้วย Google (ไม่บังคับ)** — ใช้ชื่อจากบัญชี Google เป็น "ผู้บันทึก" อัตโนมัติ ไม่ต้องพิมพ์ชื่อทุกครั้ง (ถ้าไม่ตั้งค่า จะถามชื่อครั้งเดียวแล้วจำไว้ในเครื่องแทน)
- สร้าง QR Code เฉพาะของแต่ละจัมโบ้ (1 จัมโบ้ : 1 QR Code) ดาวน์โหลดไปพิมพ์ติดป้ายจริงได้
- สแกน QR ด้วยกล้อง (รองรับกล้องหลัง/หน้าอัตโนมัติ ลดขนาดภาพก่อนสแกนให้เร็วขึ้น) → **ขึ้นแค่ 2 ปุ่มใหญ่ทันที: "ใช้งาน" กับ "ชำรุด"** แตะปุ่มเดียวบันทึกเสร็จ แล้วพากลับไปหน้าสแกนให้อัตโนมัติเพื่อสแกนใบถัดไปต่อเนื่อง (มีเมนูเลือกเองสำรองไว้ และข้อความแจ้งเหตุผลเจาะจงเมื่อเข้ากล้องไม่ได้)
- **ปุ่ม "ชำรุด"** ตีจัมโบ้ใบนั้นเป็นของเสียทันที ล็อกไม่ให้บันทึกการใช้งานต่อได้อีก พร้อมบันทึกว่าใคร/เมื่อไหร่เป็นคนตี
- แจ้งเตือนเมื่อใกล้ครบและครบกำหนด (ล็อกไม่ให้บันทึกเพิ่ม)
- ดูรายละเอียด/ประวัติการใช้งานทั้งหมด ดาวน์โหลด QR พิมพ์ใบปะหน้า Summary หรือลบจัมโบ้ ได้จากลิงก์ "ดูรายละเอียด/ประวัติทั้งหมด" ในหน้าจัมโบ้แต่ละใบ
- ส่งออกข้อมูลทั้งหมดเป็นไฟล์ Excel (.xlsx)

## การนำขึ้นใช้งานจริง (3 ขั้นตอนหลัก)

### 1) ตั้งค่า Google Sheet + Apps Script (ทำครั้งเดียว)

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ (ตั้งชื่ออะไรก็ได้ เช่น "Jumbo Tracker Data")
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ `Code.gs` ที่แนบมาในนี้แทน
4. แก้ค่า `SECRET_TOKEN` ในบรรทัดแรกๆ ของโค้ดเป็นรหัสลับที่ตั้งเอง (ยาวๆ สุ่มๆ)
5. เลือกฟังก์ชัน `setupSheets` จากช่องเลือกฟังก์ชันด้านบน แล้วกด **Run (▶)** ครั้งเดียว
   (ครั้งแรกจะขอสิทธิ์เข้าถึงสเปรดชีต ให้กด Allow) จะได้ชีต `Jumbos` และ `Usage`
   พร้อมข้อมูลตัวอย่าง
6. กด **Deploy → New deployment** → เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   → กด **Deploy** แล้วคัดลอก **Web app URL** ที่ได้ (รูปแบบ
   `https://script.google.com/macros/s/xxxxx/exec`)
7. เปิดไฟล์ `index.html` ด้วยโปรแกรมแก้ไขข้อความ ค้นหาตัวแปร `APPS_SCRIPT_URL`
   และ `APPS_SCRIPT_TOKEN` แล้วแทนที่ด้วย URL และรหัสลับที่ตั้งไว้ในข้อ 4 จากนั้นบันทึกไฟล์

> **หมายเหตุความปลอดภัย:** Web app URL + token เป็นเพียงการป้องกันเบื้องต้น
> (ใครมีทั้งสองค่านี้จะเรียกดู/แก้ไขข้อมูลในชีตได้) จึงไม่ควรเผยแพร่ URL นี้
> ต่อสาธารณะโดยไม่จำเป็น

### 2) ตั้งค่า Google Sign-In (ไม่บังคับ แต่แนะนำ)

ขั้นตอนนี้ทำให้ผู้ใช้ล็อกอินด้วยบัญชี Google แล้วระบบดึงชื่อมาใช้เป็น "ผู้บันทึก" ให้อัตโนมัติ
ไม่ต้องพิมพ์ชื่อทุกครั้งที่สแกน ถ้าข้ามขั้นตอนนี้ไป เว็บจะถามให้พิมพ์ชื่อครั้งเดียวแล้วจำไว้ใน
เครื่องนั้นแทน (ใช้งานได้เหมือนกัน เพียงแต่ต้องพิมพ์ชื่อเองครั้งแรกในแต่ละเครื่อง)

1. ไปที่ [console.cloud.google.com](https://console.cloud.google.com) → สร้างโปรเจกต์ใหม่ (หรือใช้ร่วมกับโปรเจกต์เดิมก็ได้)
2. เมนู **APIs & Services → OAuth consent screen** → เลือก User Type เป็น **External** →
   กรอกชื่อแอป/อีเมลติดต่อ → Save
3. เมนู **APIs & Services → Credentials** → **Create Credentials → OAuth client ID**
4. Application type เลือก **Web application**
5. ช่อง **Authorized JavaScript origins** ใส่ URL เว็บของคุณ เช่น
   `https://<ชื่อบัญชี>.github.io` (ไม่ต้องมี path ต่อท้าย) → **Create**
6. คัดลอกค่า **Client ID** ที่ได้ (รูปแบบ `xxxxxxxxxx.apps.googleusercontent.com`)
7. เปิดไฟล์ `index.html` ค้นหาตัวแปร `GOOGLE_CLIENT_ID` แล้วแทนที่ด้วยค่าที่คัดลอกมา บันทึกไฟล์

> **ข้อจำกัด:** Google Sign-In ต้องเปิดผ่านเบราว์เซอร์จริง (Chrome/Safari) เช่นเดียวกับกล้อง
> สแกน QR — ถ้าเปิดจากแอป LINE/Facebook จะล็อกอินไม่ได้ ต้องกดเปิดในเบราว์เซอร์ก่อน
> ชื่อที่ได้จากการล็อกอินใช้เพื่อระบุตัวตนสะดวกๆ เท่านั้น ไม่ใช่การยืนยันตัวตนที่เข้มงวดระดับ
> รักษาความปลอดภัยของข้อมูล

### 3) ขึ้นเว็บบน GitHub Pages

1. สร้างบัญชี GitHub (ถ้ายังไม่มี) ที่ [github.com](https://github.com)
2. สร้าง repository ใหม่ เช่น ตั้งชื่อ `jumbo-tracker`
3. อัปโหลดไฟล์ `index.html` (ที่แก้ `APPS_SCRIPT_URL`/`APPS_SCRIPT_TOKEN` และ `GOOGLE_CLIENT_ID`
   ถ้าตั้งค่าไว้ แล้ว) และ
   `README.md` เข้า repo — กด **Add file → Upload files** บนหน้าเว็บ GitHub ได้เลย
   ไม่ต้องใช้คำสั่ง git ก็ได้ (ไม่ต้องอัปโหลด `Code.gs` ขึ้น GitHub ก็ได้ เพราะไฟล์นั้น
   ใช้แค่ฝั่ง Google Apps Script เท่านั้น)
4. ไปที่ **Settings → Pages**
5. หัวข้อ Source เลือก **Deploy from a branch** → Branch เลือก `main` และโฟลเดอร์ `/ (root)`
   → กด **Save**
6. รอประมาณ 1–2 นาที จะได้ลิงก์เว็บรูปแบบ
   `https://<ชื่อบัญชี>.github.io/jumbo-tracker/`
7. เปิดลิงก์นี้จากมือถือ/คอมพิวเตอร์ของพนักงานได้เลย เนื่องจาก GitHub Pages เป็น
   **HTTPS อยู่แล้ว** กล้องสแกน QR จึงใช้งานได้ทันที

> หมายเหตุ: ทุกครั้งที่แก้ไขไฟล์ `index.html` แล้วอัปโหลดทับใน repo เว็บจะอัปเดตให้อัตโนมัติ
> ภายในไม่กี่นาที

## ย้ายข้อมูลเดิมจาก Firebase มาที่ Google Sheet

ถ้าเคยใช้เว็บเวอร์ชันก่อนหน้าที่เก็บข้อมูลไว้ใน Firebase มาก่อน ใช้ไฟล์
`migrate-firebase-to-sheets.html` ที่แนบมาด้วย เปิดจากเครื่องตัวเองโดยตรง (ไม่ต้องอัปโหลด
ขึ้น GitHub) กรอก `firebaseConfig` เดิม และ Web app URL + Token ของ Google Sheet ใหม่
แล้วกด "เริ่มย้ายข้อมูล" ระบบจะคัดลอกจัมโบ้และประวัติการใช้งานทั้งหมดให้อัตโนมัติ ทำครั้งเดียว
แล้วลบไฟล์ทิ้งได้เลย

## โครงสร้างไฟล์

```
jumbo-tracker/
├── index.html                      ← ตัวเว็บแอปทั้งหมด (ต้องแก้ APPS_SCRIPT_URL/APPS_SCRIPT_TOKEN ก่อนใช้งานจริง)
├── Code.gs                         ← โค้ดสำหรับวางใน Google Apps Script (ไม่ต้องอัปโหลดขึ้น GitHub ก็ได้)
├── migrate-firebase-to-sheets.html ← เครื่องมือย้ายข้อมูลจาก Firebase ใช้ครั้งเดียว (ไม่ต้องอัปโหลดขึ้น GitHub)
└── README.md                       ← เอกสารนี้
```
